**What it is genuinely good at.** It has a huge, fast memory: 1 TB/s and 16 GB. A normal gaming card of 2019 had about half the bandwidth or half the memory. For simulations that sweep big grids again and again, bandwidth and capacity decide the speed. That is this card's strength. Its arithmetic is good (13.8 TFLOPS) but not unique. Its fast FP64 and packed FP16 are real but hard to reach from a browser (section 3).
**What it lacks.** No ray tracing hardware. No mesh shaders. And it sits behind a narrow link: uploading big data from the Mac costs; the card should hold its data and compute in place. A PCIe 3.0 x4 link moves 2.7 GB/s, while the card's own memory moves 1000 GB/s: a ratio of about 370 to 1. Anything that goes back and forth over the cable wastes the card.

**What a user must download, for the OpenCL FP64 route (so Harry can decide).** Python 3 (likely already there or about 30 MB), `pyopencl` and `numpy` (a few tens of MB from PyPI). No driver download: OpenCL ships with macOS (Medium). Risk: Apple may remove OpenCL in a future macOS (it has been deprecated for years: a real long-term risk, Medium); a Python install touches nothing else if done in a virtual environment (`python3 -m venv`); `pip` installs from the network once, then everything runs offline. **Can it run as a fixed, checksummed script under the hardware rules (no network at run time, no model-written code)?** Yes: one reviewed script such as `fp64_probe.py` and a SHA-256 for it, a pinned `requirements.txt` with hashes (`pip install --require-hashes`), run with the network off. I did NOT write or install it; it is a proposal.

## 3. Using FP64 and packed FP16: honest answer
- **Packed FP16 (2x arithmetic, half the memory traffic).** Real on this card. Reachable from WebGPU only if `shader-f16` is available on this adapter; unreachable from WebGL2. Worth using later for particle fields and cloud densities where 3 digits are enough; not for water depth (float16 has about 3 decimal digits: a 2 m deep sea cannot show a 1 mm wave). Gain: small at our scale because we are not arithmetic-bound (section 4 of `GPU_WORLD_SIMULATION.md`: under 1 percent of the card's arithmetic).
- **FP64 (about 3.4 TFLOPS).** **No, not worth the install for gameplay or for hydrology in this game.** Reasons: (1) Float32 is enough for the water: the prototype matched the float32 reference, kept volume to 1e-7, and a 1 mm change on 2 m of depth is 5e-4 of the value, well within float32's 6e-8 relative precision. (2) The decisions that must be exact are made on the CPU, where JavaScript already computes in 64-bit doubles. (3) A GPU FP64 result is still not bit-identical across GPUs, so it does not solve determinism (see `GPU_WORLD_SIMULATION.md`). (4) A numpy float64 reference on the CPU already gives an accurate check for any GPU result. (5) The only route on a Mac is deprecated OpenCL, which cannot be used in the browser page. The one niche where FP64 would help is an offline reference for a very long, very large simulation, and the CPU does that overnight without installs. **Verdict: skip FP64; revisit only if a test shows float32 errors in a long-running world simulation.** (Medium-High on the verdict.)

## 4. The five-minute check Harry can do (no installs)
1. Open a page with `chrome://gpu`: look for "GL_RENDERER" and "Graphics Feature Status". If the renderer says the AMD card (not "Intel" or "Apple"), Chrome uses the external card for WebGL.
2. Open Activity Monitor, Window, GPU History, with the page running. The graph that moves belongs to the card doing the work. (Search text suggests this check, [graphics-dev](https://groups.google.com/a/chromium.org/g/graphics-dev/c/Q_29VVa-Vfc).)
3. In the browser console on any HTTPS page: `navigator.gpu && (await navigator.gpu.requestAdapter()).features` shows if WebGPU is present and whether `shader-f16` is listed; also `(await navigator.gpu.requestAdapter()).info`.
4. Make sure the TV is plugged into the Razer box and set as the primary display (Apple's rule, [Apple support](https://support.apple.com/en-qa/102363)).
The results settle three open questions: which GPU, WebGPU availability, f16.

## 6. LEAN IN: the five things most worth building to use this card
Ranked by (player payoff) divided by (cost and risk). Tier means the quality tier where it lives.

| # | Build | Why this card | Player payoff | Cost | Risk | Tier |
|---|---|---|---|---|---|---|
| 1 | **A resident 1024 to 2048 squared shallow-water world around the island**: tides, river mouths, floods, boat wakes, rain rings, kept entirely on the card, with a coarse summary to the CPU | bandwidth and capacity; nothing crosses the cable | the sea and coast visibly live; rivers fill after rain; wet sand follows the tide; a flood is an event | medium: the prototype is the base; add tide forcing, a bed from the world data, a rendering pass, a coarse readback | medium: float render targets, tuning, determinism rule | ultra (1024), high (256 to 512) |

**Is FP64 worth the install?** No (section 3). **What the card cannot give us:** hardware ray tracing (do reflections with screen-space tricks and baked light), and mesh shaders.
**Also, offline:** Blender Cycles on Metal can use this card for overnight bakes (ambient occlusion, light, caustics, water mask textures) with no change; check on the first overnight run that 3.6 sees the external card (found no 3.6-specific report; Low).
